## 🚨 P0 — Bugs bloquants à corriger en priorité

### P0-1. Pipeline cron arrêtée — données vieilles de 16 h

**Symptôme**
- `data.generated_at = 2026-04-30T16:35:57Z` alors que l'audit tourne à `2026-05-01T10:50Z` → âge **18 h 14 min**.
- Footer affiche « Données il y a 16 h ».
- `data.today = "2026-04-30"` (la veille de la date système).
- Bandeau dashboard rouge : « Données obsolètes — je ne te donne pas de picks ».

**Impact**
- Tout le path Top picks / Locks / Combinés du jour est désactivé via `_dataIsStale`.
- Les countdowns « dans Xh » sont calculés à partir de `now` mais les dates de match sont indexées sous le **mauvais `data.days[YYYY-MM-DD]`** — d'où des matchs qui se sont déjà joués mais affichent un compte à rebours positif (Tianjin vs Wuhan TT 13:35 du 30/04 affiché « dans 2h47 » alors qu'il a eu lieu 21 h plus tôt).

**Hypothèses de cause**
1. Le workflow `.github/workflows/refresh.yml` n'a plus tourné depuis 30/04 ~18:35 (cron throttling GitHub Actions sur repo inactif → cf. note dans CLAUDE.md sur cron-job.org).
2. Le PAT cron-job.org a expiré (CLAUDE.md mentionne expiration 2026-05-22, théoriquement encore valide mais à vérifier).
3. Le job a planté silencieusement (un fetcher qui throw → arrêt de la chaîne sans alerte Discord).

**Fix demandé**
- [ ] Vérifier l'historique des runs GitHub Actions sur les dernières 24 h.
- [ ] Si throttle GitHub : reconfigurer cron-job.org POST `workflow_dispatch`.
- [ ] Ajouter un health check qui appelle Discord si `now - data.generated_at > 30 min`.
- [ ] Recalibrer `_dataIsStale` : aujourd'hui c'est probablement `> 4h` (CLAUDE.md), mais on devrait aussi flag `data.today != today_local()`.
