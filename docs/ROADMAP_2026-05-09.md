## Roadmap par priorité

### 🟢 P1 — Validation passive (en cours, observation)

**Action user** : ouvrir le site, hard reload, vérifier modal détail.
Devrait afficher 20+ "Marchés alternatifs" au lieu de 5 pour matchs foot top-5.

**Markers de succès** :
- Modal d'un match Bundesliga affiche `Plus de X buts (1.5/2.5/3.5)`, `Handicap`, `Total but équipe`
- Modal d'un match NBA affiche `Total points`, `Handicap basket`, `Total points équipe`
- Modal d'un match MLB affiche `Total runs`, `Run line`
- Modal d'un match NHL affiche `Puck line`, `Total buts`

### 🟠 P2 — Modèle quality (HIGH IMPACT, 2-3 jours)

**Pourquoi** : Brier 0.231 (proche random 0.25), CLV pick-level -2.5%

**Tâches** :
1. Re-run `backtest_v2.py` sur fenêtre étendue après v50.0/v50.5 (form_stats restored)
2. Calibration per-marché pour les 16 nouveaux marchés (corners, cards, exact_score, etc.)
3. Investiguer CLV négatif : pourquoi cotes prises pires que fermeture ?
   - Hypothèse 1 : odds_history.jsonl freeze trop tôt (avant que le marché bouge)
   - Hypothèse 2 : fetch toutes les 5 min mais snapshot que toutes les 30 min
   - Hypothèse 3 : modèle trop agressif sur les outsiders dont la cote baisse

**Outputs attendus** :
- backtest_report_v2.json reflétant nouvelles features
- calibration_per_sport_league_market.json étendu pour 16 nouveaux marchés
- Diagnostic CLV avec actions concrètes

### 🟡 P3 — Featurisation des nouveaux marchés (1-2 jours)

**Pourquoi** : v50.5 expose 16 markets mais le rendering modal pourrait être enrichi

**Tâches** :
1. Modal "Marchés alternatifs" — ajouter colonne "Conviction" (haute/moyenne/faible) basée sur prob × edge

3. Combinés multi-marchés — autoriser `corners_ou + 1n2` même match (pas redondant) mais bloquer `1n2 + double_chance` (redondant)
4. Page `#tous` — filtre par marché (déjà existant via `tousFilters.marketType`, étendre le dropdown)

### 🟣 P4 — Tier-2 leagues coverage (2-3 jours)

**Pourquoi** : Süper Lig, Greek SL, La Liga 2, Eredivisie 2 — 0% lineups/refs

**Tâches** :
1. Étendre `LEAGUES` dict dans `fetch_lineups_soccer.py` + `fetch_referees_soccer.py` à plus de leagues (déjà partial via Sprint 60, mais coverage incomplete)
2. Investigation : `season_id` auto-detect peut être faux pour leagues secondaires
3. Frontend : badge "📊 Données limitées" sur cards tier-2 (déjà via `computeDataQuality` mais pas surfacé visuellement)

### 🔴 P5 — Performance & dette (sprint dédié, 5-10 jours)

**Pourquoi** : legacy-app.js = 1.9 MB, 35K lignes, 680 références v37*/v40*/v45*

**Plan ESM split** (déjà documenté `docs/LEGACY_APP_SPLIT_PLAN.md`) :
- Phase 1 : extraire helpers utiles (`utils.js`, `format.js`, `dom.js`) — 1 jour
- Phase 2 : extraire model code (`predictMatch`, `selectBestMarket`) → `src/model.js` — 2 jours
- Phase 3 : extraire pages (`renderDashboardPage`, etc.) → `src/pages/*.js` — 3 jours
- Phase 4 : extraire data layer (`PRONOSTICS_DATA`, parsers) → `src/data.js` — 1 jour
- Phase 5 : optimisation imports (lazy load par page) — 2 jours

**Effort total** : 9-10 jours-dev. Risque : moyen-élevé (régressions possibles sur 35K lignes).

## Dépendances externes / blocages

- **Sofascore IP rate limits** sur GH Actions runners — workaround via merge_existing patterns. Fix permanent : VPS proxy.
- **The Odds API free tier 500/mois** : limite consensus markets injection. Upgrade $30/mois → 100K calls.
- **Winamax API non-officielle** : fragile, peut casser. Backup via odds_aggregator (consensus 30 books).
- **GH Pages deploy lag** : 5-10 min entre push et CDN refresh. Acceptable mais frustrant pour hotfix.
