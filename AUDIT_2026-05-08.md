## BUG-001 — Sticky position cassé sur toutes les pages (topbar/nav/headers de table scrollent au lieu de coller)

- **Sévérité** : critique
- **Page** : toutes (#dashboard, #tous, #performance, #bilan, #historique, etc.)
- **Viewport** : tous
- **Reproduction** :
  1. Va sur https://harotensnor.github.io/paris-sportif/pronostics.html#dashboard
  2. Scroll vers le bas de 500 px (molette)
  3. Observe le haut de la page
- **Attendu** : la topbar (logo + nav + Profil) reste collée en haut de l'écran ; le trust strip "JOUER COMPORTE DES RISQUES" reste visible.
- **Constaté** : la topbar, le nav, le trust strip ET le toolbar de tableau (`.v36-table-toolbar`) ainsi que les `<th>` sticky du tableau scrollent tous hors écran. L'utilisateur perd toute navigation contextuelle dès qu'il scrolle.
- **Cause probable** : `body { overflow-y: auto }` (et `overflow-x: hidden`). Cela transforme `<body>` en faux scroll-container : `position: sticky` cible body comme ancêtre overflowable, mais le scroll réel a lieu sur `<html>` (`htmlScrollTop=500`, `bodyScrollTop=0`). Conséquence : tous les sticky calculent par rapport à un viewport qui ne bouge pas, donc ils suivent le scroll au lieu de stick.
- **Vérification JS** :
  ```js
  // Avec scrollY=500, getBoundingClientRect().y des sticky :
  // .rg-risk-bar  → y=-500 (top:0)   → DOIT être 0
  // .topbar       → y=-459 (top:32)  → DOIT être 32
  // .topbar-nav   → y=-399 (top:88)  → DOIT être 88
  // .v36-table-toolbar → y=-178 (top:0) → DOIT être 0
  ```
- **Fix proposé** : retirer `overflow-y: auto` (et `overflow-x: hidden`) sur `body` et `html` dans `app.css`. Laisser `<html>` être le scroll container naturel. Si l'overflow-x:hidden est nécessaire pour bloquer un débordement précis, le poser uniquement sur `<html>`, pas sur `<body>`.
- **Fichier impacté** : `app.css` (chercher `body{` et `html{` qui posent overflow)

## BUG-002 — Premier visit : 3 modals overlap simultanément (consent + onboarding + tour guidé)

- **Sévérité** : critique
- **Page** : toutes (déclenchement au boot)
- **Viewport** : tous
- **Reproduction** :
  1. Console : `localStorage.clear(); sessionStorage.clear();`
  2. Recharge https://harotensnor.github.io/paris-sportif/pronostics.html
  3. Attends 4 s
- **Attendu** : un seul modal à la fois. Idéalement : RGPD consent d'abord → puis onboarding → puis (optionnel) tour guidé.
- **Constaté** : les trois s'affichent en cascade visible :
  1. `.docs-onboard-card` "Tour guidé · étape 1/8 — Le tableau du jour" (panneau central)
  2. `.onboard-card` "ÉTAPE 1/3 — 🔥 Les gros coups d'abord — Passer le tutoriel" (modal classique)
  3. Modal "Confidentialite locale" (RGPD) en arrière-plan
- L'utilisateur ne sait pas lequel dismiss, et certains se chevauchent illisiblement.
- **Cause probable** : trois flows d'onboarding indépendants sont déclenchés au boot sans coordination. Probablement trois IIFE ou trois `setTimeout` séparés.
- **Fix proposé** : ajouter un orchestrateur `_bootSequence()` qui chaîne `await consentModal()` → `await onboardingModal()` → `await tourGuide()` séquentiellement. Chaque étape ne s'affiche que si la précédente est terminée. Stocker l'état dans `localStorage.boot_step` (`consent_done`/`onboarding_done`/`tour_done`).
- **Fichier impacté** : `legacy-app.js` (chercher `onboard-overlay`, `docs-onboard`, `Confidentialite locale`)

## BUG-003 — Routes hash deprecated redirigent silencieusement vers d'autres pages

- **Sévérité** : critique
- **Page** : SPA navigation
- **Viewport** : tous
- **Reproduction** :
  1. Va sur https://harotensnor.github.io/paris-sportif/pronostics.html#top
  2. Note l'URL après le boot
  3. Idem pour #locks, #matchs, #methodologie, #favoris, #simulator
- **Attendu** : ces hash existent dans CLAUDE.md comme pages SPA valides (`#top` = "Top picks du jour" Sprint 81 ; `#methodologie` = page méthodologie ; `#favoris` = "Favoris & alertes" Sprint 70-72).
- **Constaté** : redirections silencieuses vers d'autres pages :
  - `#top` → `#dashboard`
  - `#locks` → `#dashboard`
  - `#matchs` → `#dashboard`
  - `#methodologie` → `#academie`
  - `#favoris` → `#profil`
  - `#simulator` → `#profil`

## BUG-005 — Modal détail : Escape ferme le modal mais ne nettoie pas le hash URL

- **Sévérité** : critique
- **Page** : #dashboard, #tous, #combines (toutes pages avec liste cliquable)
- **Viewport** : tous
- **Reproduction** :
  1. Va sur https://harotensnor.github.io/paris-sportif/pronostics.html#dashboard
  2. Clique sur une ligne de pick → modal détail s'ouvre, URL devient `#match/<id>/synthese`
  3. Appuie sur Escape
- **Attendu** : modal fermé ET URL revient à `#dashboard`. Hard refresh ne réouvre pas le modal.
- **Constaté** : modal correctement fermé (`document.querySelectorAll('.modal-backdrop.open').length = 0`), mais `location.hash` reste `#match/755098/synthese`. Conséquence : un refresh ou un partage de lien dans cet état réouvre un modal sur une page de fond inattendue.
- **Cause probable** : le handler Escape ne fait que `closeModal()` sans appeler `history.replaceState({}, '', '#previousPage')`.
- **Fix proposé** : dans le handler Escape (et le bouton `.modal-close`), après `closeModal()`, ajouter `history.replaceState(null, '', '#' + (window._previousPage || 'dashboard'))` pour restaurer le hash. Sauvegarder `_previousPage` au moment où le modal s'ouvre.
- **Fichier impacté** : `legacy-app.js` (chercher `closeModal`, `Escape`, `keydown`)

## Suggestions UX (pas des bugs, mais améliorations)

1. **`#dashboard` ressemble très fortement à `#tous`** (même structure : date chips + table picks). Soit fusionner les deux (l'un est superflu), soit différencier visuellement (#dashboard = vue éditoriale "Top 5" + raisons + opportunités, #tous = liste brute filtrable).

2. **Le KPI strip "0 Big Bets · +0.0% ROI flat"** est trompeur : sur 647 picks réglés, `0 Big Bets` et `+0.0% ROI` suggère soit un bug data, soit une période trop courte. Soit ajouter une période claire (ex : "ROI 30j: +X.X%"), soit cacher cette ligne tant que les chiffres ne sont pas significatifs.

3. **Refresh-indicator** rouge "🔴 7h12 🔄" est anxiogène et omniprésent. Quand le data est stale, plutôt afficher un bandeau temporaire "Données du DD/MM HH:MM" en haut de page, et garder un compact dot + tooltip dans la topbar.

4. **`Vues sauvegardées` card** : remplacer la sticky par un picker discret dans la topbar (icône bookmark + dropdown des vues). Libère 220 px de gauche sur toutes les pages.

5. **Onboarding** : 8 étapes "Tour guidé" + 3 étapes "Onboarding principal" = 11 étapes au premier visit. C'est beaucoup. Réduire à 3 étapes max (chacune avec 1 phrase + 1 illustration) et offrir "Découvrir + tard" partout.

6. **Search bar** dans la topbar a un placeholder "Rechercher match, équipe, ligue..." mais aucune action visible. Ajouter un raccourci clavier visible (`⌘K` à droite du placeholder) et lier au Cmd-K palette existant.

7. **`Tier` colonnes "Acceptable / Solide / Sûr / Big odds / Outsider"** : la sémantique n'est pas claire pour un débutant. La page Académie devrait être linkée explicitement depuis la colonne header (tooltip cliquable).

8. **Bottom-bar disclaimer "JOUER COMPORTE DES RISQUES"** : RGPD français ANJ exige cette mention, donc la garder. Mais sa position en sticky-top crée beaucoup d'overhead vertical (41 px × toutes les pages). Considérer de la fixer en bas (sticky-bottom) où elle gêne moins.
